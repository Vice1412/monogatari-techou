## 1. 會反覆踩的坑（本檔的核心價值）

### 1.1 把 `⚠️` 或打勾符號寫進自己的程式註解

至少六次，最近一次是 2026-10-08。**每一次都被 `npm run test:emoji` 當場抓到**——
也就是說自動化關卡有效，但你**寫的時候就別用**，不要依賴事後攔截。

- 掃描範圍是 `src/` **與 `shared/`**。新增原始碼目錄時記得同步掃描範圍，否則新目錄會變成盲區。
- 排版字符（`★ ❖ ✦ ✕ ※ △ ◈ ▽ ▼ ◆ ● ◷ ✎ ✓ ✗ ➔ ①~⑤`）**允許**，不屬違規。

### 1.2 `scratch/` 裡的東西會與源碼脫鉤

`scratch/` 已列 `.gitignore`（**刻意不進版控**）。因此：

- **測試一律放 `tests/`**，不要放 `scratch/`——放那裡會與源碼脫鉤，而且不會被版控記錄。
- 唯一的例外是 `scratch/pre-purge-backup.git`（見 §3），那是刻意保留在版控外的備份。
- `resources/`（官方原書節錄與他人漢化）**已移出版控但仍在 git 歷史裡**，且 repo 是公開的。
  這是**已知的版權曝險，使用者知情**——不要「好心」去動它，那件事已經結案（見 §3）。

### 1.3 官方原書在專案目錄之外，且頁碼偏移因書而異

原書在 `<TRPG 資料夾>\Fabula ultima\`。涉及《FU》專有子系統的實作前**必須先抽取原書逐條核對**
（`GEMINI.md` 規則二.4）——**嚴禁憑記憶編造檢定、數值、等級階級**。

⚠️ **頁碼偏移因書而異**：Core 與三本 Atlas 是 **PDF = 印刷 + 2**，特典合輯是 **+0**。
**引用頁碼前先確認該書的偏移，不要沿用上一本的。**（抽取方式見 `docs/rulebooks.md`。）

### 1.4 同一個事實寫在多個檔案 = 必然分岔（本檔自己的教訓）

本檔就是這個坑的受害者（見開頭那段）。同一種病在本專案至少中過三次：
`+undefined` 顯示錯誤（兩檔四處讀同一個不存在的欄位）、金手指來源標記、本檔的待裁定清單。

**判準**：寫下一段資訊前先問「**這段話之後會變嗎？**」會變的 → 寫進有守門人的檔案（`AGENTS.md`／`decisions.md`）；
不會變的（歷史教訓、除錯方法）→ 才可以寫進本檔。

### 1.5 `git push` 在 WorkBuddy 的 bash 環境永遠掛住

harness 的 PortableGit 把自己的 `etc/gitconfig` 設成 `credential.helper = helper-selector`——
那是**會彈 GUI 視窗的互動式選擇器**，它不讀 `GIT_TERMINAL_PROMPT=0`，
所以在無 GUI 環境下就卡在那裡等認證（沒有輸出，最後被 SIGTERM）。

**解法：改用系統 Git。**

```bash
GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=never \
  "/c/Program Files/Git/bin/git.exe" push origin main
```

系統 Git 的 helper 是 `manager`（GCM 2.7.3），且 Windows 憑證管理員裡已有 GitHub 憑證。

**診斷方式**：`git config --show-origin --get-all credential.helper`——
來源若是 `WorkBuddyAI/resources/vendor/PortableGit/etc/gitconfig`，就是撞上這個坑。

### 1.6 譯名／用字爭議：「聽起來對」不是證據，`grep` 也不是

規則書的用字**不是我能決定的**，也不該由語感決定。2026-10-29 的例子：
修補匠【小工具】的階級寫成「基礎／進階／上位」，官方是「基礎／**高級**／**最高**」。

- **不能靠 `grep`**：「進階」「上位」在別的職業裡都是**正確**的字，搜到它們不代表寫錯。
- **不能靠語感**：三個詞在中文裡都通順，選哪個都「讀得出來」。
- **能靠的只有一件事**：**兩份互相不能抄襲的來源逐字一致**。
  那次是助手抽取（`scratch/complete_15_classes_raw.txt` L1172–1173）與民間漢化寫出同一個字。

**判準：凡是「這句話該怎麼寫」的問題，去找第二份獨立來源；找不到就留白，不要挑一個順口的。**

### 1.7 寫下「App 做不到」之前，先去把資料在哪裡找一次

2026-10-29 拆掉一條**立案理由寫錯**的缺陷：當時記的是
「忠實夥伴的物種 App 不知道你選了哪個」——實際上 `wayfarerData.companion.species`
一直存在，只是沒有人去讀。那條錯誤的「做不到」被當成設計決策傳了兩輪。

**代價**：錯誤的「做不到」比沒有立案更貴，因為下一個人不會再去查一次。

**相關但不同的兩層，不要併成一個數字**：
「**語法上讀得懂**」和「**現在有答案**」是兩件事。條件依賴玩家還沒填的資料時
（例如還沒設計夥伴），語法層判得出來、執行層仍然要問玩家。
兩層的數量會不一樣，兩個都要留著並寫清楚差的是哪幾條——併成一個，下次一定有人拿錯的那個去對。

## 2. 除錯方法（比結論更有用的東西）

### 2.1 驗證「公開 repo 有沒有不該公開的檔案」——三層都要查

只查工作樹會得到**錯誤的安心**。這三層的差別是本專案實際踩出來的：

```powershell
git ls-files <path>                                      # 索引層（現在有沒有被追蹤）
git check-ignore -v <path>                               # 忽略規則（有沒有被排除）
git rev-list --objects --all | Select-String "<path>"    # 歷史層（真正會漏的那一層）
```

**為什麼第三層最重要**：`git rm --cached` ＋ `.gitignore` 只防止**未來**再被追蹤，
對**已經推出去的歷史**毫無作用。公開 repo 要真正移除檔案，只有「改寫歷史 ＋ force push」一條路。

#### 2.1.1 2026-10-27 的清理結果與兩個常設約定

**常設約定一：文件裡的路徑是佔位符。** `本專案根目錄` 與 `<TRPG 資料夾>` **不是真的路徑**，
是為了不把作者的磁碟機代號、工作區資料夾名、Windows 帳號名寫進公開 repo 而換的。
看到它們時請以**目前工作目錄**為準；找不到原書就直接問使用者，不要照字面去找。

**常設約定二：`docs/` 是給人看的，不是給使用者下載的。** `deploy.yml` 的 `publish_dir: ./dist`，
`gh-pages` 分支只有建置產物（18 個檔，0 個 `.md`、0 個 `docs/`）。
所以「研究紀錄會不會被使用者下載」的答案是**不會**——只有 `git clone` 的人才看得到。
這條要記著，否則每次有人問都會重新查一遍。

**常設約定三：repo 維持公開，不要建議改 private（2026-10-27 GM 裁定）。**
理由不是「不在乎隱私」，而是**改了會把網站弄下線**。GitHub 官方文件寫得很清楚：

> GitHub Pages is available in **public repositories with GitHub Free** …,
> and in public and private repositories with **GitHub Pro** and above.

本專案的部署完全靠 Pages（`deploy.yml` → `gh-pages`）。所以對 Free 方案而言，
「改 private」與「網站關掉」是同一件事。清理已經把該藏的都藏了（見下面兩個坑），
**剩下只有歷史層**——要刻意去翻特定舊提交才看得到，代價不值得拿網站換。

> 真的要走這條路時，正確順序是：**先確認帳號是不是 Pro**（學生方案送的也算）→ 是 Pro 就直接改；
> 不是 Pro 就先把部署搬到 Vercel／Cloudflare Pages（兩者免費方案都支援私有 repo）→ 再改 private。
> **不要先改 private 再想辦法救網站。**

**清理時踩到的兩個坑：**

1. **`gitignore` 不等於 untracked。** `scratch/` 早在 `.gitignore` 裡，但 `scratch/port_builder.cjs`
   是專案第一個 commit 就進去的，所以一直在版控、一直在 GitHub 上（內容含 `C:\Users\...`）。
   判準是 `git ls-files scratch/`，不是「我有沒有寫 gitignore」。
2. **「替換次數 > 0」不等於「換對了」。** 這次的替換規則寫成 `e:///E:/...`，
   但真實字串是 **`file:///`**——正則從最後那個 `e` 起匹配，於是換出 46 行 `](fil./src/...)` 的壞連結，
   而**每一條替換都回報「命中 57 次」**。所以批次替換之後不只要斷言「換到了」，
   還要**抽樣看換出來的樣子**（這與 §2.4「批次文字替換之後一定要先建置」是同一個道理）。

### 2.2 手機版寬度的量測陷阱

`chrome --headless --window-size=390` 的**實際視窗是 500px**（Chromium 有最小寬度）。
「手機版橫向溢出」經常是**截圖工具的假象**。要驗真手機寬度得用 iframe。
（本專案為此誤報過一次 bug，詳見 `docs/decisions.md` §AT。）

### 2.3 護欄綠燈 ≠ 行為正確

**「測試全過」只等於「測試問的那個問題，答案對了」。**
本專案遇過三次「測試自己壞掉，而表現與程式全對一模一樣：全綠」。
**唯一能分辨的方法：故意把程式弄壞，看測試會不會叫。** 這件事要做，不是「有空再做」。

**「字串包含」型斷言（`html.includes('某字串')`）特別危險**：當渲染邏輯改變
（例如從「並列顯示」改成「只顯示已選用」），字串可能仍在畫面上——只是出現在**別的區塊**。
斷言不會叫，但行為已經錯了。要嘛用錨點切片限定範圍，要嘛改用**出現次數**
（「剛好 N 顆」而不是「至少有一顆」）。這條教訓在 §AW9（第 5 條）和 §BC5 各踩過一次。

### 2.3.1 紅燈先分類：是我弄壞的，還是它本來就在描述舊行為？

2026-10-27（P13）修 F-025 與 F-011 時各撞一次。**修好之後測試變紅，而那兩條紅燈
不是回歸，是斷言一直在記錄那個缺陷**：

- F-025：「倖存者①是敘事選項，不改任何數值」——那正是要修的 bug。
- F-011：`blockerCount === 3`——那個 3 之所以是 3，就是因為同一個缺口被算了兩次。

所以看到紅燈的第一個動作不是改程式，是問：**這條斷言當初是照著「正確行為」寫的，
還是照著「當時看到的行為」寫的？** 前者要修程式，後者要修斷言（並在斷言旁邊寫下為什麼改）。

**改斷言時要留住它原本想守的東西**。F-011 那條原本順帶守著「算條數不是算步驟數」，
數字從 3 改成 2 之後那個意義就沒了——所以另外確認 `每步 errorCount 加總 ＝ blockerCount`
這條獨立斷言還在，才敢改。

### 2.3.2 量「有沒有」之前，先確認「它什麼時候才存在」

同一個坑已經踩第 4 次（P12 量 K2、P13 量第 5 步空狀態）。P13 那次是：
要驗第 5 步的空狀態說明，但種子卡把「金手指／底力技／營地活動」三個開關都打開了，
**空狀態根本不會渲染**——量到的是「這句話不存在」，看起來像文案沒改。

**固定問法**：① 這東西在什麼狀態下才出現？② 它長在哪個容器？③ 才問它在不在。
如果狀態組合太多，換判定單位（逐畫面數 → 逐項目查全站）。

### 2.3.3 測試輔助函式回傳的型別，會決定斷言是真的還是假的

`cdp.mjs` 的 `clickText()` 回的是物件（`{ok, x, y, tag, text, ...}`），不是布林值。
P13 拿它直接跟 `true` 比，得到一條 FAIL——**但點擊其實成功了**（下一條斷言證明彈窗開了）。
假 FAIL 和假綠燈一樣浪費時間，而且更容易誤導（它讓你以為功能壞了）。

**寫斷言前先看一眼輔助函式回什麼。** 回物件就取 `.ok`，不要靠 `JSON.stringify` 剛好相等。

### 2.3.4 寫著「自動生成」的檔案，不一定可以重跑

F-029 改名後，`scripts/gen-optional-rules-checklist.mjs` 裡有一行同樣的舊字串，
於是「順手重跑生成器讓文件同步」——`git diff` 顯示 98 行進、98 行出。
不是換行差異：**112 個手動打好的 `✔` 全被洗回 `☐`**。

`docs/playtest/checklist-optional-rules.md` 標題寫「自動生成」，但它是**手填台賬**：
生成器永遠只吐 `☐`，勾選是人工作業的成果。**重跑＝歸零。**

**判斷方法**：數一下生成器吐的預設符號在現有檔案裡剩幾個。
若遠少於總數（此處 16 vs 112），那份檔案就不是純生成物，**只能手改**。

### 2.3.5 改畫面標題，會靜默弄壞不在版控的驗證腳本

P13 把第 5 步改名成「英雄技能與金手指」，版控內的測試全綠（它們讀 `CREATION_STEPS`，跟著改）。
但 `scratch/` 的實機腳本是用**畫面文字**當導航錨點（`gotoTab('英雄技能與特質')`）——
改名後找不到按鈕、沒切到第 5 步、後面的斷言全部落空，4 條 FAIL。
**「52/52 實機全過」是改名之前量的**，出貨後才補量。

**規則**：動到 `CREATION_STEPS`／`TABS`／任何畫面標題後，
**手動重跑一次 scratch 實機腳本**——它們不在版控，壞掉不會有任何紅燈。

**附帶**：`scratch/run-live.mjs` 的 cwd 是專案根，`shot()` 的 PNG 會落在**根目錄**，
跑完要搬回 `scratch/`，否則根目錄會多出未追蹤檔案。

**第二次踩到（2026-10-27，P15）**：這次不是步驟標題，是**名冊卡上的按鈕**。
P14 的 `p14-f018-ui.mjs` 用 `clickText('編輯', { exact: true })` 進編輯器；
到了 P15，`src/` 裡**已經找不到任何「編輯」字樣**（那個位置現在叫「構築與成長」），
於是整支腳本從第一步就全紅——**而它當時是 11/11 過的**。

教訓更精確的版本：**「驗證過」是對某個版本的畫面驗證過，不是對產品驗證過。**
`scratch/` 的腳本用畫面文字當錨點，而畫面文字是最常被改的東西。
→ 只要動過任何按鈕／標題／步驟名，就把相關的 `*-ui.mjs` 全部重跑一次；
成本是幾分鐘，代價是不重跑就會拿著一份過期的「全過」去說服自己。

**第三次踩到（2026-10-27，P16），換了一個樣子：不是文案變了，是「等待時間不夠」。**
`p16-ui.mjs` 的 `loadRoster()` 寫成「點『角色卡助手』→ 等 1000ms → 點『確定進入』→ 等 2600ms」。
實際上前一步的轉場要 1.4 秒，`確定進入` 那時**還沒畫出來**，`clickText` 默默失敗，
於是整段（甲）在「名冊根本沒開」的狀態下量測——四條全紅。
**紅的原因不是產品，是我量錯了地方**，而它看起來和「功能壞了」一模一樣。

規則補一條：**實機腳本的每一步都要斷言「我真的到了那一頁」**，不要靠固定毫秒數。
P16 的修法是 `if (!entered.ok) throw new Error('名冊沒有開起來')`
＋ 進場後比對「畫出來的卡片數 === 塞進去的卡片數」。這兩個檢查讓同一支腳本
第二次跑就 22/22——而它第一次跑是 0/4。

**第四次踩到（2026-10-27，P17）：這次是「修好的東西」把它弄壞的。**
F-008 讓角色卡助手**不再彈「開發中提醒」**，於是那顆「確定進入」按鈕**不該存在了**——
而 P15／P16 的實機腳本正是靠點它才進得去名冊。它們不是被改壞的，是**被修好的**。

這種壞法比前三種更難察覺：前三種是「我改了文案」，這一種是「我照著缺陷報告把缺陷修掉」，
而**修掉缺陷本來就是對的**。→ 動到**流程**（不只文案）時，相關實機腳本一律重跑。

**順帶一個會讓「全過」變成假的寫法**：實機腳本若寫 `try { … } finally { process.exit() }`，
中間拋錯時 `finally` 直接結束行程，畫面只印出前面幾段的全過訊息——看起來像成功。
P17 第一版就是這樣：甲 12/12 印完就結束，乙丙丁戊根本沒跑。**加 `catch` 把例外印出來**，
並且問一句「通過 N/N 的 N 應該是多少」。

### 2.3.6 掃字串只能證明「有人寫過」，不能證明「畫得出來」

P17 修 F-016 時，職業魔石區塊的護欄是這樣寫的：

```js
check('職業魔石區塊也有作廢說明', mnemoSrc.includes('mnemosphere-suppressed-note-'), true);
```

刻意破壞把整段 JSX 條件改成 `{false ? ( … ) : null}` 之後——**那串字還在檔案裡**，
護欄全綠，畫面一個字都不印。12 條破壞裡唯一「沒抓到」的就是它。

**這是「護欄綠燈 ≠ 行為正確」最乾淨的一個例子**：那條護欄檢查的不是行為，是字串的存在。
它保護的東西（畫面上有沒有這句話）**它從來沒看見過**。

規則：**`src.includes('x')` 只適合守「不准出現」**（例如「全站不得再出現某病句」）。
要證明**畫得出來**，就得真的畫一次——用 `renderToStaticMarkup` 把元件渲染出來再檢查輸出。

### 2.3.7 掃描範圍不含「缺陷住的那一段」，規則就永遠不會叫

P34 寫 `tests/requirementWording.test.mjs` 時，12 條「不准出現」全部掃
`heroicSkillExtraPrerequisite()` 的回傳值——也就是**「額外前提」那一段**。
破壞驗證當場抓到三條**弄壞了也不叫**：`職業，且`、`中，且`、`，並`。

原因不是護欄太弱，是**那三個缺陷依定義不在那一段裡**：
職業段的語尾在職業段、連接詞在接縫，而額外前提是從「，且」後面才開始的。

→ 修法：每條規則標 `scope: 'extra' | 'full'`，依「**這個缺陷會落在哪一段**」分流。

**放寬也要量。** 想順手把 `必須` 一起改成掃整句，量到 **3 條**等級門檻句
（「且你的角色等級必須為30或更高」，雙重詠唱／偉大召喚／偉大召喚【變體】）是官方原文的合法用法
→ `必須` 留在 `extra`。**收緊和放寬都要有數字撐著，不然就是憑感覺調參數。**

※ 這是「掃描邊界」的第 6 次（前五次見 `MEMORY.md` 鐵則 13），但換了樣子：
　 前面是**目錄邊界**，這次是**段落邊界**。**「這個缺陷會出現在哪裡」和「我要掃哪裡」是兩個問題。**

### 2.3.8 「那一頁存在」不等於「那一頁有東西」

P34 的實機腳本第一次跑出 `0 / 4`：五個場景全部停在同一步。
導航每一顆按鈕都點得到、`rows: 0`——**頁面確實到了，但表格是空的**。

原因：卡片用了 **5 級**。第 5 步「英雄技能與金手指」在 5 級時顯示「沒有需要設定的項目」，
**英雄技能選擇器根本不會出現**（5 級沒有英雄技能名額）。P33 的實機場景全部是 10 級卡，
所以照抄過來就踩到了。

→ 修法有兩件事，缺一不可：
　 ① 卡片改 10 級；② `gotoPickerFor()` 改成回傳 `'ok'` 或 **`'fail:第N步'`**——
　　 紅的時候要一眼看出卡在哪，而不是只看到 `false` 再猜一次。

**判準：實機腳本不能只斷言「我點到某一頁」，還要斷言「那一頁上有我預期的東西」。**

### 2.4 批次文字替換之後一定要先建置

用正則批次改 import 陳述式時踩過：單行與多行格式不同，正則只在單行正確，
多行檔案被改壞。**是 `npm run build` 抓到的，不是測試**——因為測試跑的是已打包的產物。

### 2.4.1 PowerShell 不是「透明的字串搬運工」：三種字元它會自己吃掉

同一件事在本專案發生過三次，每次症狀都不像「被吃字」：

| 寫法 | 它吃掉什麼 | 症狀 |
|---|---|---|
| `Set-Content -Encoding utf8`（PS 5.1） | 多寫一個 **BOM** | 下一支 `ConvertFrom-Json` 讀檔失敗 |
| `@'…'@` here-string 餵給 `.Replace()` | **CRLF**（here-string 一律 CRLF，檔案是 LF） | 替換靜默不匹配 → 改了但沒生效 |
| `@"…"@` here-string 寫 JS 模板字串 | **反引號**（PS 的跳脫字元） | `` `t `` 變成 TAB、`` `src` `` 被吃掉 → `ReferenceError: document is not defined` |

**規則：要寫含反引號、`$`、模板字串或中文長段落的檔案，用 `write`／`edit` 工具，不要用 pwsh 拼字串。**
若非得用 pwsh，單引號 here-string `@'…'@` 是唯一安全的（但它只保護 `$` 與反引號，不保護換行），
而檔案寫入一律用 `[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`。

### 2.4.2 只寫 JSX 不匯入 `React`：`build` 綠、`test` 紅

**新增元件時最容易漏、而且症狀完全不像「少一個 import」的坑。**

| 執行環境 | JSX runtime | 需要 `React` 在作用域內？ |
|---|---|---|
| `npm run build`（Vite／esbuild automatic） | automatic | 不需要 |
| `npm test`（`tests/*.test.mjs` 的 esbuild bundle） | **classic** | **需要** |

所以一個只寫 JSX、沒 `import React` 的元件，建置完全乾淨，**只在 SSR 護欄裡炸**：

```
ReferenceError: React is not defined
    at EmptyState (file:///…/.test-build/characterLog.mjs:5811:3)
```

堆疊只指到 bundle 裡的行號，看不出是哪支源碼。**新元件一律顯式 `import React from 'react';`**
（本專案的既有元件幾乎都這樣寫，原因就是這個）。

> 這個坑的價值在於它的**順序**：先跑 `build` 再跑 `test` 的習慣會讓人以為「建置過了就沒問題」。
> 兩個環境用不同的 JSX runtime，**其中一個綠不能證明另一個也綠**。

### 2.5 手動 E2E 稽核（`scripts/audit-npc-workshop.mjs`）

NPC 工坊的功能稽核腳本，**不進 `npm test`**（CI 沒有 Chrome，且它需要 `npm run dev` 在跑）。

```
npm run dev                                  # 另一個視窗，http://localhost:3000
node scripts/audit-npc-workshop.mjs          # 需本機 Chrome；CHROME_PATH／CDP_PORT 可覆寫
```

**它驗的是「行為」不是「渲染」**：真的打字、真的按鈕、真的上傳檔案、真的下載檔案，
並用 CDP 攔 `navigator.clipboard` 驗複製內容。`exit 0` 才代表全過。

腳本裡已經封裝了六個**會讓人誤報 bug** 的陷阱，改腳本前先讀：

| 陷阱 | 症狀 | 對策（已寫進腳本） |
|---|---|---|
| viewport 不等於 `--window-size` | 角色卡整段不進 `innerText`（`xl:` 以下被隱藏）→ 誤判「預覽壞了」 | `Emulation.setDeviceMetricsOverride` 設 1600×1000 |
| 手風琴是**切換**語意 | 已展開時再按等於關起來 → `cards=0` | `openAccordion()` 先看有沒有 body 再決定要不要按 |
| `deepest()` 取 document 順序最後一個 | 「完整」按鈕與「切回『完整』」提示句同名 → 按到提示句，什麼都沒發生 | `clickButtonExact()` 只在 `<button>` 上找 |
| `Page.reload` 會清掉注入的 `window.*` | clipboard 墊片失效 → 「複製成功」驗不到內容 | 墊片在 reload **之後**才裝 |
| 章節是 lazy chunk + 翻頁鎖 | 剛退出封面時章節卡 `onClick` 被 `transitionState` 擋掉；進場後還顯示「正在展開章節……」 | 等 850ms 動畫結束；等該字串消失才斷言 |
| 非 `workshop` 章節有開發中提醒 | 點了章節卡不會翻頁，畫面停在封面 | 還要再按「確定進入」 |

> **有效性已驗證**（2026-10-22）：故意把搜尋篩選改成 no-op、把 Discord 格式的回傳值改成空字串，
> 稽核精準 FAIL 在對應的 4 項、其餘 79 項照樣綠；還原後 83/83 全綠。

### 2.6 建角草稿的端到端稽核（`scripts/audit-npc-draft.mjs`）

`audit-npc-workshop.mjs` **刻意不 reload**（reload 會清掉注入的墊片與 `window.__t`），
所以「草稿寫進真 localStorage → 真 reload → 接回建角頁 → 提示條兩顆按鈕」這段
沒有任何常態關卡在守。這支腳本補的就是那一段，同樣**不進 `npm test`**：

```
npm run dev
node scripts/audit-npc-draft.mjs                 # GM_BASE 可覆寫網址
```

兩個新踩到的陷阱（與 §2.5 那六個不重複）：

| 陷阱 | 症狀 | 對策 |
|---|---|---|
| 腳本跑完不返回 | 明明做完了，終端機一直掛著；配上 `\| Select-Object` 看起來像「完全沒輸出」 | 收尾 `api.proc.kill()` ＋ `process.exit(code)`；進度用 `process.stdout.write` 即時印，不要等 `report()` |
| 封面章節卡不是按鈕 | `querySelectorAll('button')` 找不到「NPC工坊」；`innerText === 'NPC工坊'` 也找不到 | 卡片是 `<div>`，文字是「NPC工坊／完整功能／點擊翻開」；用 `startsWith('NPC工坊') && includes('點擊翻開')` 取最深一層，且**先等 1600ms** 讓翻頁鎖解除 |

> ⚠️ **§BR5 的教訓**：當時那支探測腳本用完就刪（`scratch/` 不進版控），覆蓋率當場歸零。
> **能重跑的探測才叫護欄，跑一次的不算**——所以這次留在 `scripts/`。
