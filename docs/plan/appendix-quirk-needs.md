# 金手指（Quirk）：需要玩家「填資料」或「反覆操作」才會生效的條目

> 規劃稿，不含實作。範圍：`src/features/character-sheet/data/rulesData.json` → `quirks[]` 共 46 筆。
> 原文行號＝該條 `desc` 在 `rulesData.json` 的那一行（`desc` 是單行 JSON 字串，行號已用腳本重新量過）。
> 前次稽核（是否算得出來）見 `scratch/flows/quirk.json`；本稿只回答「點了之後還有沒有事要做」。

---

## 1. 判準

### 1.1 這份稿在問什麼

使用者原話：「我要檢查這些技能信息有沒有點了之後，面板上就必須要有相應操作，而非文字而已就能運作。」
所以本稿**不是**問「引擎算不算得出來」（那是 `quirk.json` 的事），而是問：
**選完這條金手指之後，玩家是否還得輸入一段原文要求的資料、或在跑團中反覆做同一個操作，效果才會成立。**

### 1.2 分級

| 級 | 判準 | 落點 |
|---|---|---|
| **A** | 需要 ≥2 個**非數值**欄位（名字／外表／描述／對象選擇／自訂條目），而且跑團中會**反覆**用到這份資料或做多種不同選擇 | 需要新面板（新分頁或新區塊）＋新的角色資料欄位 |
| **B** | 只需要**一個數字**（0–N 的刻度／計數器）或**1–2 個純文字欄位**，操作只有加減／歸零／一顆按鈕 | 現有 `ClassResourceStrip`／`ClockTracker`／一段文字欄位就能裝 |

「需要另開面板」與「一個計數器就夠」的分界就是**資料的形狀**：
有名字、有外表、有「這一組是給誰的」、或同一個資料要在不同場合被選不同分支 → 面板；
只有「現在幾點」→ 計數器。**例外**：計數器的加減不是固定值而是「擲 1d6 加減」時，仍算 B，但需要一個**擲骰式加減**的按鈕（現有 `ClassResourceStrip` 只有固定值重置，見 §2.4）。

### 1.3 排除線（不列入）

1. **純衝突內生效**（戰鬥視窗另做）：瞄準規則、傷害加值、相性、形態、場景內骰階。→ 不列入，但在 §4 註明「移交戰鬥視窗」。
2. **純常駐數值且引擎已算**：只要面板顯示得出來即可，玩家沒有任何事要做。
3. **純敘事**：原文沒有任何點數／次數／欄位（例如只有「問 GM／建立聯繫人」）。
4. **能力旗標**（例如「獲得施展元素學派儀式的能力」）：那是 `spellGrants` 的缺陷（它不讀金手指），
   不是「玩家要填資料」，屬 `quirk.json` 的 `partial`，不在本稿。

### 1.4 統計

- **列入：35 筆**（A 級 17／B 級 18）
- **不列入：11 筆**
- 需要**新通用元件**：4 個（§5）

## 2. 可照抄的範式：底力技（zeroPower）

底力技是站上**唯一**已經做完「刻度 ＋ 每次操作 ＋ 章節結算 ＋ 額外資料」的子系統，本稿全部照它寫。

### 2.1 資料形狀
- `character.zeroPower` 單一物件，欄位含 `name`／`triggerId`／`effectId`／`choices{}`／`clock`／`variant`／`awakened`／`combinedPairs[]`
  （`data/zeroPowers.js:393` `createZeroPowerState`）。
- **空的就是空的**：建角不替玩家選（`zeroPowers.js:389` 註解）。金手指的 `quirkData` 應沿用同一原則。
- 讀取一律經 `normalizeZeroPower`（`zeroPowers.js:460`）：壞資料收斂、舊存檔回空狀態、不拋錯。

### 2.2 純函式層
`utils/zeroPower.js` 把「現在能不能用」收成**單一判定入口** `canUnleashZeroPower`（`:117`，回 `{ok, reason}`），
介面只負責停用按鈕與顯示 `reason`。金手指的「能不能用這個增益」應比照。

### 2.3 edit／play 共用一個元件
`ZeroPowerBlock`（`components/ZeroPowerBlock.jsx:288`）用 `mode='edit'|'play'` 同時服務建角第 5 步與跑團面板，
檔案頭（`:1-12`）寫明理由：拆成兩個元件之後「編輯端能選的組合」與「跑團端認得的組合」遲早分歧。
→ 金手指的資料面板也應該只有一個元件、兩個 mode。

### 2.4 缺口：現有計數器**不能擲骰**
`ClassResourceStrip` 的重置是**固定值**（`ClassResourceStrip.jsx:121-132` 呼叫 `writeValue(resource, resource.resetTo)`）。
而金手指有五處原文是「恢復／降低 **1d6**」（富家子弟、實驗逃亡體、遺物使用者、地獄差生、被詛咒之人），
把 `resetTo: 0` 當成「恢復 1d6」是**規則錯誤**（會直接清零）。
→ 這是本稿要求的新通用元件之一（§5.1）。

### 2.5 履歷
`LOG_KINDS` 是**封閉詞彙**，未登記的 kind 一律拒收（`utils/characterLog.js:39`、`:168`）。
金手指操作若要寫履歷，必須先在 `LOG_KINDS` 註冊（建議 `quirk`，`coalesce: 0`），
`LOG_FIELD_LABELS` 已有 `quirk: '金手指'`（`:105`）可直接沿用。

## 3. 逐筆

> 格式：原文要求／需要玩家填的資料／跑團中的操作／需要引擎算的／現況／建議落點。
> 「待裁定」＝原文沒寫、或站上既有政策未定，不自行發明。

### quirk:富家子弟（A）
- **原文要求**（`rulesData.json:2351`）：「你身邊還跟著2個非常忠誠的保鑣：給他們一個名字，描述一下他們的外表。」「每當你使用這些增益時，你的保鑣會累積1d6點疲勞值；當他們累積到10點或更多疲勞值時，你就不能再依賴他們了。」「每當章節結束……你的保鑣會恢復1d6點疲勞值（最低降為0）。」
- **需要玩家填的資料**：保鑣①姓名（字串，必填）、保鑣②姓名（字串，必填）、兩人外表描述（長字串，必填）——由「給他們一個名字，描述一下他們的外表」要求。疲勞值為共用單一數字（0–10）。
- **跑團中的操作**：①使用增益時三選一（「小心！」傷害減半／「這是您先前需要的情報」休息時問 GM 一個問題／「臥倒，我會處理好的！」元素水晶額外傷害）→ 每次使用 +1d6 疲勞值；②章節結束 −1d6 疲勞值（最低 0）。
- **需要引擎算的**：疲勞上限 10（達 10 停用全部增益）；元素水晶額外傷害＝`5 + 等級一半`（向下取整）；章節結算的 1d6 加減。
- **現況**：疲勞值池已存在但只有加減與「歸零」（`data/classResources.js:116`、`ClassResourceStrip.jsx:121`），
  **「恢復 1d6」被寫成 `resetTo: 0`**；保鑣姓名／外表無任何欄位；三種增益無按鈕；
  `startingZenitBonus` 已接（`characterEngine.js:1695`）；但編輯器「移除」直接寫 `quirk` 欄位、繞過帳本（`CharacterEditor.jsx:2290`）。
- **建議落點**：新 `character.quirkData` → `{ bodyguards: [{name, look}, {name, look}], fatigue: 0 }`；
  面板放在跑團面板常駐區（與 `ClassResourceStrip` 同一區，`CharacterPlayHUD.jsx:4837`）之後，或新分頁 `quirk`；
  增益按鈕掛在該區塊，按下後寫履歷 `kind: 'quirk'`。順手修 `CharacterEditor.jsx:2290` 改走 `buildQuirkPatch`。

### quirk:被束縛的心（A）
- **原文要求**（`rulesData.json:2246`）：「你與那個塑造你的一個NPC或組織建立起一個羈絆……只要你擁有這個金手指，那麼這個羈絆就不會因為任何方式失去或消除」「為這個NPC或組織創造他們至關重要的3條戒律」「當你在每個場景中第一次違反戒律時，你會立即受到動搖和虛弱狀態效果，並失去當前一半的HP和MP（向下取整）的懲罰，但也會獲得2點物語點」「當你累積違反了6次戒律之後，你再違反戒律時將忽略受到的懲罰」「在第7次違反戒律時，你將失去這個金手指」。
- **需要玩家填的資料**：羈絆對象（NPC／組織名稱，必填）、3 條戒律（三條字串，必填）、累計違反次數（0–7）。
- **跑團中的操作**：每場景**第一次**違反戒律時按一次（+1 次數、+2 物語點、扣半血半魔、上動搖／虛弱）；第 7 次觸發退場與英雄技能。
- **需要引擎算的**：次數 0–7；「本場景已觸發過」旗標（每場景只能領一次）；≥6 次後免罰；第 7 次改寫主題並發英雄技能。
- **現況**：羈絆是通用功能（`character.bonds[]`，`CharacterPlayHUD.jsx:4413`），但沒有「不可移除」旗標
  （刪除鈕存在，`CharacterPlayHUD.jsx:1746`）；戒律與違反次數完全沒有欄位；物語點可用通用帳本手記（`utils/fabulaPointsFlow.js:154`）。
- **建議落點**：`quirkData.vow = { bondId, precepts: ['','',''], violations: 0, lastSceneId }`；
  「本場景已領」需要一個場景邊界（見 §6 待裁定 ③）；面板需 3 個輸入框＋一顆「違反戒律」按鈕。

### quirk:光榮的命運（A）
- **原文要求**（`rulesData.json:2261`）：「當你獲得這個金手指時，寫下這則有關於你的預言。」「在每個章節結束時……從以下5個選項中選擇一項」。
- **需要玩家填的資料**：預言全文（長字串，必填）；章節末的 5 選 1 選擇紀錄。
- **跑團中的操作**：章節結束時五選一（實現／符合／無關／違背／打破）→ 恢復全部 HP/MP/狀態、或 +1／+6 物語點、必要時移除金手指＋發英雄技能。
- **需要引擎算的**：五個分支各自的後果（恢復量、物語點加減）；選擇「實現」或「打破」後金手指失效。
- **現況**：無預言欄位；無章節結算流程（跑團面板只有聚會 EXP 小工具，`CharacterPlayHUD.jsx:525`）；
  英雄技能選器已有（`CharacterEditor.jsx:2514`）。
- **建議落點**：`quirkData.prophecy = { text, outcomes: [{chapter, choice}] }`；章節結算做成面板上的 Modal（與 EXP 結算同一節奏），
  結果寫履歷（`kind: 'quirk'`）。

### quirk:老載具（A）
- **原文要求**（`rulesData.json:2271`）：「你可以從《核心規則》（第125頁）中獲得一輛你所選擇的交通工具」「這輛交通工具的大到足以容納你和團隊的其他成員，再加上2~3名客人，但它不適合戰鬥」「每個章節限一次……GM可能會給你2點物語點」。
- **需要玩家填的資料**：載具名稱（必填）、交通工具類型（原文指向 p.125 清單，例如陸地座駕／船隻／飛艇——**清單本身待裁定是否要內建**）。
- **跑團中的操作**：章節限一次的 GM 獎勵（GM 決定，非玩家按鈕，見 §6 待裁定 ⑦）。
- **需要引擎算的**：無（承載人數與「不適合戰鬥」是敘事約束）。
- **現況**：載具子系統只有機師的 `pilotVehicle`（`components/companions/PilotVehicleModal.jsx:27`；
  `characterEngine.js:2080` 只讀 `char.pilotVehicle`），非機師沒有任何收件處。
- **建議落點**：`quirkData.vehicles[] = [{ name, kind, size, notes }]`；
  三條載具金手指（老載具／偷來的載具／行動工作站）共用同一個「交通工具」面板區塊（§5.2）。

### quirk:天才的宿敵（A）
- **原文要求**（`rulesData.json:2293`）：「選擇一項你擅長的領域：儀式、技能或咒語。然後，說明誰是你的宿敵：這個NPC將成為一個次要反派（擁有5點終結點），你對他建立起1種羈絆，並在讚賞和自卑之間選擇一種情緒」「你可以花費1點物語點來忽略這次成本」。
- **需要玩家填的資料**：領域（三選一，已存在 `options`）、宿敵姓名與描述（必填）、對宿敵羈絆的情緒（讚賞／自卑，必填）。
- **跑團中的操作**：①花 1 物語點忽略一次 HP/MP 成本（不定時）；②宿敵在場時失敗檢定需強制轉大失敗（衝突內，移交戰鬥視窗）。
- **需要引擎算的**：1 點物語點折抵；宿敵終結點 5（NPC 子系統不在角色卡）。
- **現況**：`options` 三項只有 id/label、**沒有 effects**（`rulesData.json:2293` 之後的 `options` 區塊）；
  宿敵 NPC 與羈絆情緒無欄位；忽略成本無入口。
- **建議落點**：`quirkData.nemesis = { field, name, look, feeling, bondId }`；「忽略成本」做成施法／技能花費旁的一顆小按鈕（或面板上的「本次成本歸 0」開關）。

### quirk:應劫之人（A）
- **原文要求**（`rulesData.json:2319`）：「描述你為這個世界帶來了什麼樣的劫數」「當某個規則或能力需要你花費HP、MP或物語點時，你可以讓你的劫數進度推進一步，以此來忽略這次成本」「在每個章節結束時……骰2d20。如果你骰的結果等於或低於你目前的角色等級，那麼你帶來的劫數進度就會提升一個進度」「當你帶來的劫數進度達到9時，你失去這個金手指」。
- **需要玩家填的資料**：劫數名稱與描述（必填）；劫數進度（0–9 刻度）。
- **跑團中的操作**：①每次「忽略成本」→ 進度 +1（由玩家描寫預兆）；②章節結束骰 2d20 → 達標則進度 +1（40 級以上無條件 +1）。
- **需要引擎算的**：進度上限 9、達 9 的退場；2d20 ≤ 等級的判定（需角色等級）；40 級以上特例。
- **現況**：無劫數欄位、無進度刻度、無章節骰（`data/classResources.js:112-171` 的五個金手指池不含它）。
- **建議落點**：`quirkData.calamity = { name, desc, progress: 0 }`；
  刻度用 `ClockTracker`（`src/components/ui/ClockTracker.jsx:59`，`totalSegments: 9`）嵌在面板；2d20 用擲骰器回呼（`CharacterPlayHUD.jsx:1067` 同一個入口）。

### quirk:交織的靈魂／戒指裡的老爺爺（A）
