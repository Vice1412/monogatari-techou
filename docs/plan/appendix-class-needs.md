## §0 先講現況：通用流程層已經解決了一半，這次要解另一半

P18／P19（`1a7c4ad`、`16f6392`）之後，`data/effectFlows.json` 已經是**執行期資料**，由
`utils/effectFlow.js` ＋ `components/SkillFlowControls.jsx` 渲染：

| 層 | 位置 | 能力 |
|---|---|---|
| 資料 | `data/effectFlows.json`（373 筆，class 145 筆） | `control.kind`＝`none/counter/toggle/button/select`，`apply.via`＝`existing/flow-control/flow-listed` |
| 引擎 | `utils/effectFlow.js:586` `flowActionPlan` | 算「按下去會發生什麼」：成本（hp/mp/ip/fp/zenit）真的扣、寫 `flowState[id]`、產生履歷；算不到的東西進 `unresolved`（`:617`） |
| 狀態 | `utils/effectFlow.js:474` `readFlowState`／`:507` `withFlowState` | `character.flowState[id] = { n, on, choice }`——**只有一個數字、一個開關、一個字串** |
| 介面 | `components/SkillFlowControls.jsx`（counter `:86`／select `:227`） | 職業技能分頁每條技能下方渲染（`CharacterPlayHUD.jsx:3967`）；`apply.via === 'existing'` 的條目跳過（`:875`），因為那些已有專屬面板 |

**所以「按不到」已經不是本輪的缺口。** class 145 筆的 `apply.via` 分布是：
**70 筆 `flow-control`**（有按鈕或計數器）、**34 筆 `existing`**（有專屬面板）、
**38 筆 `flow-listed`**（只列在資料裡、畫面上沒有控件——多半是純常駐或規則型）、
**3 筆 `none`**（就是純敘事那三筆：野性交談／博聞強記／徽記連結）。

**本輪的缺口是三種「一個數字裝不下」的東西**：

1. **清單型**：要記住 N 個具名實體（徽記在誰身上、夥伴的兩招、載具模組…）→ `flowState` 只有 `n/on/choice`，裝不下。
2. **物件型**：效果掛在**別的東西**上（藥水、美食、食材）→ 專案目前沒有「消耗品物件」，這些技能沒有宿主。
3. **多步驟／跨面板型**：播種→生長→離園、選舞步→表演→共享、擲骰前宣告→擲骰→換值、命刻→補格 → 通用按鈕只能記錄「按過一次」。

**另外還有一個現成的病**（不是本輪新增，但會被這些技能放大）：
`effectFlows.json` 裡【貿易之風】【真正的財富】【我聽說過】【小金庫】**各自畫了一個上限 `SL + 3` 的計數器**，
而 `data/classResources.js:41` 的 `tradePoints` 已經是「貿易點數，上限 SL+3」。
同一個池在畫面上有 **4 個入口**——§E 群就是要把這件事收斂成一個池。

## §A 徽記群（2 筆）

### class:徽記師:徽記學
- **原文要求**：「每次你獲得本技能，你習得**2**種徽」「你最多能**同時擁有【SL + 1】個徽記**，若你創造了多於上限的徽記，則你必須**先選擇若干個已有的徽記摧毀**」「你能以使用**庫存動作**，消耗**2 點 IP** 來創造一個習得的徽記並**選擇**：將徽記放在自己身上；將徽記放在一個可見的**盟友**身上；用裝備著的武器進行一個**自由攻擊**…將所選徽記的副本放在所有被命中的敵人身上（**每個副本都算一個獨立的徽記**，計入你的【SL + 1】上限）」
- **需要玩家填的資料**
  - 已習得的徽記種類（陣列，每筆＝19 種之一，額度 `2 × SL`，必填）→ **已有**（`skillSuboptionsData.js:813` 的 `selectedOptions`）
  - **每一枚「存在的徽記」**：`{ 符號 id, 攜帶者型別: self/ally/enemy, 攜帶者名稱, 是否為副本, 建立時間 }`（必填——原文「放在一個可見的盟友身上」「放在所有被命中的敵人身上」都要指名）
  - 摧毀時的「選哪幾枚」（原文「必須先選擇若干個」）
- **跑團中的操作**：庫存動作＋2 IP → 建立一枚並指定攜帶者；達上限時擋下並要求先摧毀（摧毀本身也是一個操作）
- **需要引擎算的**：同時上限 `SL + 1`；習得數 `2 × SL`；IP 成本 2；副本是否計入上限（是）；超上限時的合法性
- **現況**：只做了「挑選」（`skillSuboptionsData.js:813`）與一個計數器（`effectFlows.json` 的 `class:徽記師:徽記學`，`control.kind=counter`、`max="SL + 1"`，由 `SkillFlowControls` 渲染）。**缺**：徽記實體清單、攜帶者、建立／摧毀操作。`components/` 內沒有任何徽記面板（`徽記` 只出現在規則速查 `RuleCodexDrawer.jsx:164` 與子選項註解）。
- **建議落點**：**新元件** `components/companions/SymbolistMarks.jsx`（比照 `FloristGardenTracker` 掛在職業技能分頁）＋ 純函式 `utils/symbolist.js`（上限驗證／摧毀挑選）；現有的 `counter` 應改成「由清單長度推導」，否則上限會有兩個真相。19 種徽記的效果資料已在 `skillSuboptionsData.js:637`（`SYMBOLIST_SYMBOLS`），面板可直接顯示。

### class:徽記師:咒語徽記
- **原文要求**：「如果一個**盟友攜帶著你的徽記**，他能以**咒語動作**來**摧毀這個徽記**，來施展一個**你習得的咒語**，只要該咒語的總 MP 消耗小於等於**【SL × 10】**點。**由這個盟友自己來支付 MP 消耗**。」
- **需要玩家填的資料**：不需要新欄位——它要的是「A 群那張徽記清單」＋「這個角色習得的咒語清單」（後者已有 `character.spells`）。**依賴 A 群**。
- **跑團中的操作**：由**別的玩家**在自己的回合執行。本 App 不能替他扣 MP，實務上需要「把這個徽記可施放的咒語清單**交出去**」的動作（複製文字／分享）。
- **需要引擎算的**：可施放咒語＝`spells.filter(總MP ≤ SL × 10)`；摧毀後該徽記從清單移除（回扣上限）
- **現況**：`effectFlows.json` 的 `class:徽記師:咒語徽記` 是 `apply.via = flow-listed`、`control.kind = none`——**連按鈕都沒有**；也沒有任何地方讀「徽記攜帶者」。
- **建議落點**：掛在 A 群面板的**每一枚徽記卡片**上（顯示「此攜帶者可用：<清單>」），交付動作用既有的 `CopyTextButton`。不需要新面板，但**必須等 A 群落地**。

## §C 消耗品／美食物件群（5 筆）

- **建議落點**：`GourmetCookbook` 內加「完成並施加」按鈕（扣食材 → 產生一筆「美食」暫存 `character.gourmetDishes[]`，含效果與份數）＋ 一個 `settleRest()` 掛在休息／聚會面板。**不需要新面板**。

### class:美食家:加點愛

### class:美食家:鹽與胡椒

## §E 貿易點數群（4 筆）

> **現有的病**：`classResources.js:41` 已經有 `tradePoints`（上限 `SL+3`、開卡起點 2，`:46`／`:51`），
> 但 `effectFlows.json` 又把【貿易之風】【真正的財富】【我聽說過】【小金庫】各畫一個 `max="SL + 3"` 的計數器。

> **建議先做的事**：把這 4 筆的 `control` 全部改成「讀 `classResources.tradePoints`」，
> 或直接改成 `apply.via='existing'`，只在資源條留一個池。

### class:商人:貿易之風
- **原文要求**：「在一個**可以進行貿易的區域休息後**，你獲得**【SL + 1】貿易點數**」「上限【SL + 3】；角色創建時取得則以 **2 點**開始」「在**非衝突的場景**中，你可以**花費 2 點貿易點數**來**選擇一個選項**：①你**創造**一個 GM 批准的材料或稀有物品，價值 ≤【等級 × 30】z；②或者你**創造一個住在附近的 NPC**，並解釋他們的**職業**以及你們是如何認識的，然後 GM 會告訴你他們**需要什麼**來換取服務」

  - **用 2 點換來的東西**：①材料／稀有物品 → 應進**行囊**（`inventory.js` 已有 `createInventoryItem`）＋ 價值上限 `等級 × 30`

- **建議落點**：資源條上的池加兩顆動作鈕（`休息 +{SL+1}`、`花 2 點`）；「花 2 點」開一個二選一對話框（可重用 `SelectControl` 的形狀），①接到行囊新增、②新增一筆 `character.tradeNpcs[]`（欄位照原文四項）。**不需要新面板**，但需要一個新資料鍵。

### class:商人:真正的財富
- **原文要求**：「**每場遊戲環節一次**，當你幫助一個 NPC 或社群…如果你**已習得貿易之風**技能，你將獲得**【SL + 1】貿易點數**」

- **現況**：`effectFlows.json` 是 `counter`／`max="SL + 3"`——**這其實是貿易點數池的複製品**，不是「本聚會用過幾次」。缺：聚會旗標、前置技能檢查、與池的連動。

### class:商人:小金庫

## §F 跨面板／他人效果群（4 筆）

### class:靈師:支援魔法
- **原文要求**：「當你施展以一個或多個盟友為目標的咒語時，如果你裝備了**奧術**武器，你可以**選擇其中一個你對其擁有羈絆的盟友**。若如此做，該盟友**在當前場景中進行的下一次檢定**獲得加值；該加值等於你對其**羈絆的強度**」
- **需要玩家填的資料**：目標盟友（必選，且必須是「有羈絆」的）＋羈絆強度（已有 `character.bonds[].feelings.length`）
- **跑團中的操作**：施咒後指定一位盟友 → 產生一筆「該盟友下一次檢定 +N」的暫存；該盟友用掉後失效；場景結束清空

- **現況**：`flow-listed`／`control=none`（連按鈕都沒有）。全站沒有任何「暫存加值」的資料結構（`flowState` 只有 `n/on/choice`）。
