### 三個跨類別的結構性問題（施工前必須先處理，否則會白做）

1. **一條條目只能掛一顆控件**（`items[].control` 是單一物件）——【富家子弟】需要「疲勞計數器＋
   3 顆增益按鈕＋章節骰」並存。**18 筆**受影響 → W0-6。
2. **「每場景一次」其實等於「每張卡一次」**：`control.reset` 只被**印在 title 裡**，
   全站沒有任何按鈕會執行重置。**10 筆**受害 → W0-7。
3. **同一個數字有兩份**：疲勞值／不穩定值／異常值／懷疑點／顛覆點同時存在 `classResources`
   與 `flowState.n`；貿易點數被畫 **4 次**；而 `resetTo: 0` 把「恢復 1d6」實作成**清零**
   → W0-3／W0-8。職業技能還有【植生術】的「通用按鈕扣 MP 但不加種子、花園盤加種子但不扣 MP」→ W0-9。

## 2. 已裁定的決策（**不要再問，照做**）

| # | 決策 |

| D1 | 非數字資料放 **`flowState[id].fields`**，不另開 `quirkData`（遷移面積最小） |

## 4. 施工通則（細節在 `08-agy-rules.md`）

1. **一冊一冊做，每冊做完跑 `npm test` ＋ `npm run build`**，綠了才進下一冊。
2. **資料一律改 `scratch/flows/*.json`，再跑 `npm run build:flows`**；不要手改
   `src/features/character-sheet/data/effectFlows.json`（那是產物）。
3. **純函式不得擲骰、不得讀時間**；UI 只負責渲染與回呼。
4. **SSR 測不到 `onClick`**：把「按了會怎樣」抽成純函式測它；UI 測「按鈕在不在、是否 disabled、
   那行原因有沒有印出來」。
5. **每一筆都要刻意破壞驗證 ≥2 條**（改壞 → 紅 → 還原 → 綠），並寫進回報。
6. **回報格式**：`改了哪些檔（含行數）／測試數字／破壞驗證結果／哪幾筆還沒做／遇到的待裁定`。
