## 0. 三十秒版

《物語手帳》是一個**跑團用的角色卡工具**。玩家在網頁上照規則書開角色卡、算數值、
印出來帶去團裡；GM 也能用它做敵人（NPC）。純前端，資料存在瀏覽器裡，沒有帳號、沒有伺服器。

- 程式：`src/`，約 6 萬行，React 19 + Vite 6 + Tailwind 3
- 測試：`tests/` 34 道關卡，`npm test`
- 規則本體：`GEMINI.md`（最高）＞ `AGENTS.md`（執行細則）
- 現在做到哪：`docs/playtest/resume.md`
- 踩過的坑：`docs/handoff.md`

**最重要的一件事**：這個專案的問題向來不是「寫不出功能」，而是
**「數字算對了，但玩家看不懂」** 和 **「同一個判斷寫在五個地方，只修了兩個」**。
你接手後最大的價值不是加新功能，是把已經開著的 2 條缺陷收乾淨（都只記錄、不排修）。

## 1. 這個 App 是什麼（給完全沒聽過的人）

底層規則系統叫 **Fabula Ultima**（簡稱 FU），一款日式風格的桌上角色扮演遊戲規則書。
玩家要開一張「角色卡」：選職業、算 HP／MP、挑技能、買裝備、記金手指（特殊天賦）。
這本規則書的計算有點囉嗦（職業等級決定免費增益、裝備決定傷害、金手指會改相性……），
所以有了這個工具：**把規則書的算式變成介面**。

主要功能區（`src/features/`）：

| 目錄 | 是什麼 |
|---|---|
| `character-sheet/` | 主體。開卡（8 個步驟）、角色卡檢視、跑團面板（HUD）、列印 |
| `npc-workshop/` | 敵人制作工坊。GM 做怪物用，有六種定位與 Boss 技能分類 |
| `combat-tracker/` | 戰鬥輪次追蹤 |
| `clocks/` | 命運時鐘（跑團用的進度條機制） |
| `dice-roller/` | 骰子 |

角色卡的資料結構是**一個大物件**（`character`），存在 localStorage。
七個權威鍵的前綴是 `monogatari_techou_`，單一來源在 `src/data/keys.js`。
**`src/` 內禁止直接呼叫 `localStorage`**，一律走 `src/data/store.js`。

**兩條紀律**（有測試守著，但你要知道為什麼）：

1. `src/` 內不得直接呼叫 `localStorage` —— 全部走 `store.js`。
   因為舊版有 11 個鍵要遷移到 7 個權威鍵，散落各處的存取會讓遷移永遠做不完。
2. 純邏輯要抽到 `utils/` 才能測。`onClick` 裡的算術是**測不到的算術**。

**最大的兩個檔案**是 `NPCWorkshop.jsx`（4892 行）與 `CharacterEditor.jsx`（2541 行）。
它們是已知的技術債，但**沒有拆分的授權就不要動**——拆之前要先補快照護欄，
否則重構完無法證明行為沒變。

## 4. WorkBuddy 有、而你沒有的東西

這一節是**你最容易踩空的地方**。前一個 AI（WorkBuddy）有一套記憶系統與技能包，
它會在每次對話自動注入。**你讀不到那些，所以我把必要的部分抄在這裡。**

### 4.1 使用者的工作慣例

- **回覆一律繁體中文。** 他是台灣人，識別字／指令／log 保留原文。
- **他程式基礎薄弱。** 是 GM（帶團的人），不是工程師。
  技術術語第一次出現時給一句白話解釋。不要說「我把 memo 加上去就好了」。
- **他要的是「能帶去團裡用」，不是「程式碼漂亮」。**
  判斷優先序時：算錯 > 看不懂 > 不方便 > 不好看。
- **改完必須寫變更紀錄**（兩份，見 `00-start-here.md`）。他會檢查。
- **不要替他做決定。** 遇到規則書沒寫清楚的地方，回報並問，不要自己補。
  他曾經為了一條「HP／MP 二選一」裁定：「這本來就是玩家自己選的，不是 App 該決定的。」

### 4.2 量測方法論教訓（這個專案最大的隱形成本）

前一個 AI 花了大量時間在「量錯了」而不是「寫錯了」。你接手後會遇到同樣的誘惑：

1. **「有沒有」型的量測先確認狀態。** 某些文字只在特定狀態才存在
   （開職業選擇器／選過二選一／定稿後）。曾經量到 0%，實際是 50%。
   **狀態組合太多就換判定單位**：逐畫面數 → 逐項目查全站。
2. **數字對不上，先找分母定義。** 計畫書說 97、實測 84，不是算錯，
   是 97 = 84 內容 + 13 結構。**分母不同不能比大小。**
3. **「一半已修」是最容易掉進裂縫的狀態。** 它既不在「已修（該有護欄）」
   也不在「未修（等修好再寫）」的清單裡。修東西順手動到別條是常態 →
   **收場時掃一次「有沒有別條被順手動到」**（這個坑已撞 4 次）。
4. **台賬狀態會過期。** `findings.md` 標「排隊」的條目可能已被順手修掉一半。
   彙總時必須複驗高分條目現況。
5. **報告不標「數字怎麼量出來的」，它自己就會變成下一個勘誤對象。**

### 4.3 工具差異（WorkBuddy 的坑，你不一定會有）

| WorkBuddy 的限制 | 你在 Antigravity 的狀況 |
|---|---|
| 官方原書 PDF 在 shell 一律被擋（`Permission denied`） | 你可能讀得到。**先試**，讀不到再問使用者。 |

## 5. 官方原書與譯名

**這是硬規則：效果數值必須核對原書，嚴禁憑記憶編造檢定、數值、等級階級。**
（`GEMINI.md` 規則二.4）

| 書 | 用途 | 頁碼偏移 |
|---|---|---|
| 核心規則書 v1.1 | 機制最高權威 | **PDF = 印刷 + 2** |
| 高度／自然／科技奇幻手冊 | 三大擴充 | +2 |
| 官方特典合輯 | Bonus Collection | **0（無偏移）** |
| 怪物圖鑑 Vol.1 | 敵人 | — |
| 民間漢化（26 個 HTML） | **只管譯名，不管機制** | — |
| 繁中角色卡 Excel | 譯名權威（三大手冊＋特典） | — |

- 頁碼偏移**因書而異**。引用頁碼前先確認該書的偏移，不要沿用上一本的。
- 衝突時**官方英文優先**：譯名決定「中文怎麼寫」，官方英文決定「規則是什麼」。
- **「職業」定譯鐵律**：Martial 系列一律譯「職業」（職業近戰武器／職業防距武器／
  職業防具／職業盾牌），**嚴禁「軍用」**。
- 漢化是測試版且是「不全書」：查不到譯名**不等於官方沒有**，只能標記「漢化未收錄」。
- 詳細抽取方式見 `docs/rulebooks.md`。

## 6. 單一入口清單（不要在元件裡重新發明）

這個專案最貴的教訓是「同一個判斷寫在五個地方，只修了看得見的兩個」。
以下邏輯都已收斂成單一入口，**遇到相關需求先找這些函式**：

| 需求 | 唯一入口 | 為什麼 |
|---|---|---|
| 技能顯示（含變體） | `resolveSkillDisplay` | `skills[].name` 永遠是原版名，`variantId` 承載選擇 |
| 技能條目重建 | `buildSkillEntry` | 同上，20 處硬編碼查詢已收斂 |
| 免費增益二選一 | `resolveChosenBenefit()` | 曾有兩處比小寫而 UI 寫大寫，導致「履歷永遠寫 HP」 |
| 「N~M 個職業」 | `classCountRange()` / `classCountPhrase()` | 這句話曾寫在 5 處 |
| 金手指效果 | `getQuirkEffects(char)` | 回傳 `{ body, option, resistances, vulnerabilities, absorption, ... }` |
| 換金手指改起始資金 | `buildQuirkPatch` | `character.quirkZenitBonus` 是帳本，重寫加減會重複加錢 |
| 公測（Playtest）開關 | `isPlaytestAllowed(character)` | 是「開卡規則開關」不是「一本手冊」 |
| 職業名後綴剝除 | `stripClassSuffix` | 手寫 `replace('【Playtest】')` 會在下次改名時安靜回傳 0 筆 |
| 植物學家花園階級 | `isSeedEffectActiveAt(clockLabel, clock)` | 狀態只有一份 `character.floristGarden` |
| localStorage | `src/data/store.js` | 遷移鐵律：權威鍵空才複製，永不覆寫、永不刪舊鍵 |
| 九相屬性內聯 | `renderTextWithAffinities` | 原則「寧漏不誤」，判定在 `affinityText.js` |
| 第 5 步標題 | `CREATION_STEPS[4].label` | 現名「英雄技能與金手指」 |
| 術語解釋 | `data/glossary.js` + `TermHint.jsx` | 16 條，每條恰好一句。定義放 `aria-label` |
| 攻擊性咒語計數 | `countOffensiveSpells()` | 名冊的 `isOffensive` 是**唯一真相**（38 條，20 真）。**不要**用「效果文有沒有提到傷害」推論——【遲鈍】【幻覺】【激怒】不打傷害但仍是攻擊性 |
| 忠實夥伴物種是否符合 | `resolveCompanionSpeciesGate(required, actual)` | 物種在 `wayfarerData.companion.species`，**不是**「App 不知道」。沒選夥伴／物種名不認得 → 退回玩家；選了但不對 → 擋並寫出目前是什麼 |
| 英雄技能「算不到的前提」 | `heroicSkillExtraPrerequisite()` / `resolveHeroicExtraRequirement()` / `isClassOnlySegment()` | 三段：職業／等級／額外前提。**不要**用 `.slice(1)` 假設「第一段一定是職業段」——【躍空】就是反例 |
| 修補匠【小工具】的階級 | `data/gadgetBranches.js` 的節點名 | 官方是**基礎／高級／最高**（不是進階／上位）。職業技能那份原本寫錯、英雄技能那份本來就對 |
| 小工具軌的第幾檔是否符合 | `resolveGadgetTierGate(required, gadgets, { technoRestrictsEquipment })` | 軌在 `tinkererData.gadgets`（`alchemy`／`infusion`／`magitech`，0～3），**不是**「App 不知道」。**沒有紀錄 ≠ 紀錄是 0**：`null` → 退回玩家，`0` → 直接擋 |
| 英雄技能條件的寫法 | `tests/requirementWording.test.mjs` | 只有一種：`，且已習得【X】`；小工具另一種：`，且小工具【軌】已達某益處`。**新增技能時照這個寫**，寫成別的樣子護欄會紅 |
| 公測效果全文 vs 英文原文 | `tests/heroicEffectText.test.mjs` | 43 條公測＋9 條變體的效果文，數字／長度／概念三層比對。新增 Playtest 技能時**必須**更新 `tests/fixtures/playtest-en-source.json` |
| 詩人（Chanter）的術語 | `data/glossary.js` ＋ `CHANTER_DATA` | `keys`（樂句）≠ `tones`（曲風）。verse 專案譯為**樂句**，tone 譯為**曲風**。疊句的【激情】／【生動】／【莊嚴】是曲風，不是樂句 |

**改共享資料（`rulesData`）前先問「這是誰的物件」**，一律 `{ ...obj }` 複製後再改。
曾經因為直接改共享物件，造成「徒手傷害」被寫進全站所有武器。

## 7. 已定的設計決策（看起來像 bug，但不要「好心」改回去）

| 現象 | 真相 |
|---|---|
| HP／MP 二選一沒有預設值 | **刻意的**。GM 裁定「這本來就是玩家自己選的」 |
| 常駐面板預設收合 | **刻意的**。面板在編輯器八個分頁都常駐，展開吃掉第一屏一半 |
| 檢視模式看不到「切換變體」按鈕 | **刻意的**。檢視模式永不渲染切換介面，只有編輯模式能改 |
| 阿爾卡納有兩份（9 個 vs 11 個） | **刻意的**。原版與變體並列不覆寫，變體多一個【脈衝】層 |
| 敵人技能的 `ip` 是 `null` | **正確行為**。不是每個技能都有 IP 消耗 |
| 對外展示（roster gallery）不顯示英文 | **刻意的**。`withEn()` 已含並列，再加就是重複 |
| 漢化寫「見 XX 表」但介面沒有那個表 | 這是**漢化錯誤**（英文原書寫頁碼，被翻成不存在的表）。修法是補 keyword，不是改官方文字 |
| 零之元素未選完傷害類型就不畫卡片 | **刻意的**，不是漏渲染 |
| 覺醒之力找不到觸發 chips | **搬走了**，搬到覺醒區，不是不見了 |
| 術語解釋是 tooltip 不是辭典頁 | GM 裁定。不要提議改成獨立分頁 |
| 勾選框有「0 條」和「6 條」兩個數字 | **兩個都對，量的層不一樣**（P34 之後）。**0** ＝ 語法上看不懂的（`checkable: false`）已經歸零，167 條全讀得懂；**6** ＝ 選擇器現在真的會問你，因為**這張卡現在沒有答案**：4 條小工具（舊卡沒有小工具資料、或魔晶石制改寫了魔導科技軌）、2 條夥伴物種（玩家還沒設計夥伴）。**「讀得懂」不等於「現在就有答案」** |
| 小工具寫「高級」「最高」而不是「進階」「上位」 | 官方用字，兩份獨立抽取物逐字一致。**不要**因為「進階聽起來比較順」改回去 |
| 魔晶石制下【量子魔加農】仍然要玩家勾選 | **刻意的**。那一制把魔加農移除、魔導球降級（p.133），同一個「高級」指向的節點不一樣 → 照原樣判會**判錯方向**。只有「魔導科技軌＋高級以上＋魔晶石制」這個窄口徑如此，煉金術與灌注術照判 |
| 中文效果文裡沒有（O）圖示 | **刻意的**。（offensive）圖示只在英文原文出現，中文翻譯時應移除。**不要**把（O）留在中文效果文裡——它是排版記號，不是內容 |
| 頁碼引用統一寫「見《書》p.N」 | **刻意的**。核心 115 條一律「見《核心規則書》p.216」；Playtest 43 條原本寫「第 216 頁」，已統一。**同一個專案裡不能有多種寫法** |
