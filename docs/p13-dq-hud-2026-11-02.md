## 2. 導航：從兩份變一份

改之前：中欄**六顆指令格** ＋ 下方 sticky **六個分頁標籤**——同一份清單印兩次。
這就是「訊息太多、有點冗長」最具體的一處。

改之後：**只有一份**（左翼指令窗）。sticky 那條降級成「頁名條」：

```
▶ 行囊與道具   第 6 / 7 頁                    ▲ 指令
```

它保留釘住（使用者 P12 的裁定 #1 不推翻），但不再是第二份按鈕：
只有一顆「▲ 指令」把人送回指令窗。`hud-subtabs-bar` 的 testid 與 sticky 契約都留著。

## 6. 這一輪踩到的坑

1. **設計系統三條紅燈在第一天就攔下來**：`text-[10px]`（任意字級）、`#c2ae8c`（未登記 hex）、
   `rounded-[6px]`（任意圓角）。改的是元件，不是規則。
2. **測試斷言寫 `data-testid` 但原始碼是 `testId` prop**：`HudWindow` 收 `testId`，
   原始碼裡不會出現 `data-testid`。靜態斷言要驗渲染後的 HTML，不是原始碼。
3. **刻意破壞讓測試在載入期就死**：注入 `const IconComp = tab.icon;` 會參考到不存在的
   `tab` → 整個測試檔死掉、一個 check 都沒跑 → 「0 條紅」被誤讀成「護欄沒在守」。
   破壞腳本現在會分辨「沒跑起來」與「全綠」。
4. **CRLF 對 `\n`**：repo 原始碼是 CRLF，破壞腳本的錨點寫 `\n` 直接 0 次命中。
   現在讀進來正規化成 LF 比對、寫回去還原。
5. **「撐滿框高」是舊框形狀的推論，不是需求**：框從 3:4 變成更高之後，
   `object-contain` 的限制邊從高度變成寬度，圖會用滿寬、高度等比留白。
   斷言改成「等比、不裁切、至少撐滿一個方向、高度 ≥ 600」。
6. **前提比需求嚴會紅錯地方**：手機 sticky 的前提原本寫「滾到 absTop+240」，
   但 sticky 只要滾過 `absTop − 標頭高` 就接手。前提寫太嚴 → 紅在「頁面不夠長」。
