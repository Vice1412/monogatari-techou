## 三、三條路徑的實測結果

### 路徑 A：全部預設值，一路按「下一步」（`scratch/s1-pathA.mjs`）

**結論：七次點擊從第 1 步走到第 6 步，全程零攔截。**

| 步驟 | 有沒有擋 | 畫面狀態字 |
|---|---|---|
| 1 基礎身世 | 沒擋 | 尚未設定身份 |
| 2 職業與技能 | 沒擋 | 尚未選擇任何職業（起始 5 級需配置 2~3 個職業） |
| 3 四維屬性 | 沒擋 | 尚未選擇四維屬性配置 |
| 4 裝備配置 | 沒擋 | 起始資金尚未結算（原書 p.165：剩餘預算 ＋ 2d6 × 10）——目前顯示的 500z 是裝備預算，不是起始資金 |
| 5 英雄技能與特質 | 沒擋 | 特質與命刻已確認（見 F-002） |
| 6 命名與背景 | — | 角色尚未填寫姓名 |

**「不擋」本身不是缺陷**——邊填邊看是合理的。真正的問題在第 6 步：

- 頁首「完成創角」：`disabled: true`、`opacity 0.45`、`title` 講的是定稿**之後**的後果（F-005）。
- 頁尾「完成創角，進入跑團面板」：`disabled: false`，**點得進去**，落地後 `locked` 仍是 `false`、`classes: []`、四維全 0（F-004）。

> 教訓：**「按了沒反應」要先確認是不是 `disabled`。** 這次第一眼以為是壞掉，實際是正確的禁用態；真正的問題是禁用時**沒有告訴玩家缺什麼**。

### 路徑 B：經典職業搭配一鍵套用（`scratch/s1-pathB.mjs`、`s1-pathB2.mjs`、`s1-apply-verify.mjs`）

**結論：這是目前最好走的一條路，功能完全正常。**

| 檢查點 | 實測 |
|---|---|
| 彈窗規模 | **83 組**（核心 20／高度奇幻 18／科技奇幻 17／自然奇幻 18／特典合輯 10） |
| 說明文字 | 有，且逐本手冊標了原書頁碼，還寫明「含特技分配、起始裝備與資金」 |
| 搜尋 | **有**（可搜名稱／職業／特技，placeholder 給了「黑騎士、舞者、植物學家、混合變形」等例子） |
| 篩選 | 有（全部／五本手冊） |
| 展開預覽 | 點 `▽` 展開後顯示：職業＋等級徽章、四維骰、習得技能（含所屬職業）、裝備清單、剩餘資金 |
| 套用延遲 | **250 ms 內**就寫進 localStorage |
| 套用結果 | 「鍊金術士」→ `classes: [修補匠 L3, 旅人 L2]`、`attributes: {dex:8, ins:10, mig:6, wlp:8}`、`zenit: 170`、`startingFundsRolled: true`、`enabledSourcebooks` 自動補上來源書 |
| console | **零錯誤、零警告** |

**唯一的小摩擦**：卡片收合時只顯示「名稱 ＋ 來源徽章 ＋ `170z` ＋ `▽`」，`170z` 沒有標籤說明它是「剩餘資金」。展開後才從說明文字推得出來。

> **這一節同時修掉了一個誤判**：第一次測時我以為「套用沒生效」（點完資料沒變）。實際是我的腳本用 `find(x => /套用/.test(x.t) && x.t.length < 20)` 抓按鈕，**抓到的是左側欄的「經典職業搭配／一鍵套用」**（`(223,195)`），不是卡片裡的「套用此經典配置」（`(493,497)`）。改成**精確文字相等**後一次就中。
> **規則：點按鈕一律用 `textContent.trim() === '完整文案'`，不要用 regex 模糊比對。**

### 路徑 C：自己挑職業、自己配點（`scratch/s1-breakpoint.mjs`、`s1-pathC2.mjs`、`s1-pathC3.mjs`）

**結論：介面引導意外地好，但「配點」這件事本身需要一點摸索。**

職業選擇器（`ClassPickerModal`）的實際引導：

- 頂部：「已選職業：**還沒配點——在右邊點技能加號，可以連續挑好幾個職業再一起確定**」
- 右側：「**這次配了 0 級 ／ 還能配 5 級**」
- 底部：「**這次總共投入：N 級（M 個職業）**」＋動態提示
- 底部按鈕文案會隨狀態變：
  - 未配點 → 「請先分配技能等級」（disabled）
  - 配好 → 「**確定修習 2 個職業（共 5 級）**」

實測配點過程：秘儀師 4 級（「阿爾卡納圓環」上限 SL 4）→ 再點第 5 次**無反應**（F-006）→ 改點嵌合師 1 級（「吞噬」）→ 總投入 5 級 → 確定 → 落地 `classes: [秘儀師 L4, 嵌合師 L1]`。

> **這裡有一個新手會撞到的牆**：FU 的技能有各自的 SL 上限（1～5 不等），所以「想把 5 級全投在一個職業」不一定做得到。畫面**不會**告訴你「這個技能滿了，請換一個」——加號只是變淡（F-006）。

## 九、方法論教訓（給 S2 之後的自己）

1. **`innerText` 與 `textContent` 都要看，而且都不保證完整。**
   本次一度以為「右側技能卡片沒渲染」，因為 `innerText.includes('阿爾卡納閉環')` 回 `false`。
   真相有兩個：①技能名其實是「阿爾卡納**圓環**」不是「閉環」；②`textContent` 裡有 `.fu-icon` 的 glyph 字符（`wwww`）。
   **規則：比對文字前先用 `textContent` 印出前後 260 字，親眼看過再寫斷言。**

2. **`find()` 取第一個匹配＝取到錯的那一個。**
   路徑 B 的誤判就是這樣來的（抓到側欄按鈕而非卡片按鈕）。**規則：用 `===` 精確比對文案。**

3. **單次觀察不能立案。**
   S0 已經踩過一次（「名冊卡在正在展開章節」其實是 2 秒過渡）。本次「套用沒生效」也是單次觀察的假象。
   **規則：每個缺陷至少要有「兩次獨立重現」或「源碼行號」其中之一。**

4. **`disabled` 的按鈕點不動是正確行為，不是 bug。**
   真正的問題永遠是「為什麼不能按，以及有沒有說」。

5. **官方標準規則是「最空」的狀態。**
   金手指、開局英雄技能、變體全都是選用——**S2 之後若要測這些，必須先學會怎麼切換開卡規則**（第 1 步的「此團開卡規則 / 官方標準 / 展開」）。這件事本身可能是一個新手障礙，值得在 S4 之前補測。
