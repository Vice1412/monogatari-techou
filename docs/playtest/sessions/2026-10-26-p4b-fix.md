## 二、面板改版：目的不變，手段換掉

**舊設計**：自訂規則時**自動展開**。理由寫在元件檔頭（原 `:91-92`）——
「否則你只會看到一張跟別人不一樣的卡，卻不知道是哪條規則造成的」。

**問題**：這個面板在編輯器裡是**常駐**的（八個分頁都在），一展開就吃掉每一頁第一屏的一半；
而 GM 的 20 張卡幾乎每一張都是自訂的（P4 §12.6.2 的人眼判定）。

**新設計**：**一律收合 ＋ 一行差異摘要**。

```
┌──────────────────────────────────────────────────────────────┐
│ 此團開卡規則  [自訂]                                    展開 │
├──────────────────────────────────────────────────────────────┤
│ 與官方標準不同 5 條： [起始等級] [金手指] [底力技] [營地活動] [魔晶石：完整規則] │
└──────────────────────────────────────────────────────────────┘
```

原本的目的（一眼知道哪裡不同）由那行摘要承擔，成本從「半個螢幕」降到「一行」。

### 2.1 摘要不能只數 `creationRules` 的鍵

第一版直接數角色身上那份 `creationRules`，結果 R08 報「不同 6 條」，
其中一條是 `allowPlaytest: false`——**那張卡的公測修訂等於官方預設，根本沒差**。
原因：`creationRules` 是「使用者動過的欄位」，不是「現在跟預設不同的欄位」。
（開過又關掉會留下 `false`。）

第二版改用既有的 `diffCreationRules(rules)`，仍報「不同 7 條」，
多出來的是 `起始資金`、`技能點數`——而 R08 只設了 `startingLevel: 8`。

**根因**：有些欄位的差異是**算出來的**，不是設出來的。

| 設了什麼 | 自動跟著變的 |
|---|---|
| 起始等級 8 | 起始資金 500 + 50×8、技能點數 = 8 |
| 魔晶石開啟 | 職業數固定 3 |
| 公測修訂開啟 | 手冊清單自動多一本 |

### 2.2 判準：拿掉這一條，實際生效的規則會不會變？

與其為每個欄位寫死例外（下次新增規則就安靜失效），改用一條通用判準：

```js
const isDerivedRule = (rules, key) => {
  const without = { ...rules };
  delete without[key];
  return JSON.stringify(resolveCreationRules(without))
       === JSON.stringify(resolveCreationRules(rules));
};
```

不會變 → 它只是別的設定的結果，不是 GM 的決定 → 不進摘要。

R08 最終報 **5 條**，正好是 GM 真的動過的五件事：
`起始等級`、`金手指`、`底力技`、`營地活動`、`魔晶石：完整規則`。

### 2.3 兩個順手修掉的邊角

1. **超過 5 條收成「＋N」**（`DIFF_SUMMARY_MAX`）。摘要太長就失去「一眼」的意義。
2. **數不出任何一條時不渲染摘要**。`isDefault` 比全部欄位，摘要不列 `defaultSourcebooks`，
   兩者不同層，極端情況下會出現「自訂但 0 條」——那時候寫「不同 0 條」比不寫更糟。

## 三、F-019：真正的位置不在 `initial`

`findings.md` 的敘述從頭到尾寫「貿易點數缺 `initial`」。照著修會修錯地方。

只加 `initial: 2` → **畫面仍然顯示 0**。因為：

```js
// 改前
initial: def.kind === 'value' ? def.initial : null,   // 池型永遠拿到 null
```

**真正的位置在傳遞層，不在定義層。**

### 3.1 修的時候想到的第二個坑（沒有流進程式）

池型原本的讀法是 `n > 0 ? n : initial`。加完 `initial: 2` 之後：

> 玩家花到 0 → `0 > 0` 為假 → 當成「沒填過」→ 給 `initial` → **復活成 2 點**

這**比原本的 bug 更糟**：原本只是每次少 2 點（玩家不會發現），改壞之後是**無限用**。

改成看 `Number.isFinite`：`NaN`（從未寫入）才給 `initial`，`0` 就是 `0`。

### 3.2 三層驗證，缺一不可

| 層 | 驗什麼 | 結果 |
|---|---|---|
| 純函式 | `readResource` / `clampResource` 的邊界 | `test:resources` I 段 15 條全過 |
| 顯示 | 商人（【貿易之風】SL2）跑團面板 | `貿易點數 − 2 / 5 +` |
| 寫回 | 按兩次「−」→ 重載 | `2/5` → `1/5` → `0/5`（減號變灰）→ 存檔 `{tradePoints: 0}` → **重載仍 `0/5`** |

截圖：`scratch/p4b-merchant-tradepoints.png`、`scratch/p4b-trade-zero.png`。

## 四、這一輪踩到的坑：**假綠燈**

破壞驗證時，`classResources.js` 的破壞**根本沒注入成功**，而測試回報 **95/95 全綠**。

原因：該檔是 **CRLF 換行**，我的替換字串用 `\n` 寫，`String.replace` 找不到 → 靜默不換。
如果沒有察覺，結論會是「這條護欄沒用」或更糟——「這條護欄通過了」。

**修法**：破壞腳本一律加一行斷言，替換前後必須不同：

```js
if (s === orig) { console.error('!! 替換失敗，破壞未注入'); process.exit(1); }
```

**這正是 `resume.md` §1.1 已經記過的同型問題**（「破壞腳本用 `replace()` 只換第一個」），
只是換了個外觀（換行符而不是出現次數）。
