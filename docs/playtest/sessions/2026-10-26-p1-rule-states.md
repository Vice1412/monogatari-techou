## 五、結果

### 5.1 A2 真值表：**通過**

`00-plan.md` §14.9 那張表是**用實際函式印出來的**，本輪再跑一次，逐格一致（5 態 × 7 欄 ＝ 35 格）。

### 5.2 A1／A5：**通過**

- 職業數鎖：四個非 `off` 模式全部 `min === max === 3`；`off` 沒有鎖。20/20。
- `diffCreationRules` **不含** `classCountMin`／`classCountMax`（派生值不進 diff）。20/20。

### 5.3 A4 污染測試：**完全正確**（這是本輪最好的消息）

拿「守護者 ＋【雙重盾牌】SL1 ＋ 主手與副手都是盾牌」這張卡，切到五個模式驗證：

| 模式 | 裝備白名單 | 盾牌被擋 | 標「已作廢」 | 判定 |
|---|---|---|---|---|
| `off` | 否 | 0/4 | 0/4 | 正確（雙重盾牌合法） |
| `full` | **是** | **4/4** | **4/4** | 正確 |
| `integrated` | **是** | **4/4** | **4/4** | 正確 |
| `mnemospheresOnly` | 否 | 0/4 | 0/4 | **正確**（這一態不套白名單） |
| `hoplospheresOnly` | **是** | **4/4** | **4/4** | 正確 |

原話：「魔晶石制下這些技能已作廢（科技奇幻手冊 p.133）：雙重盾牌——已投入的技能點不會退還」。
**這條做得很細**：它不只擋裝備，還交代了技能點不退還。而且 `mnemospheresOnly` 正確地**不**標作廢。

### 5.4 A3 空卡驗證：**兩個發現**

`off` 的阻斷型 error 是 **2** 條；四個魔晶石模式是 **3** 條。多出來的那條與原有的那條**在說同一件事**：

```
① 尚未選擇任何職業 (起始 5 級需配置 3~3 個職業)
② 魔晶石制需恰好 3 個固有職業（目前 0 個），且升級不得新增職業
```

→ 開成 `F-011`（重複計數）與 `F-012`（`3~3` 文案失效）。

## 六、一個**假失敗**（方法論記錄）

第一版 A3 的斷言寫成「空卡的 error 不得出現非『尚未填寫』型的訊息」，於是有 16 組被判 FAIL。
實際上那 16 條全都是同一句「魔晶石制需恰好 3 個固有職業（目前 0 個）」——**它本來就是「還沒填」的意思**，
是我的白名單 regex 太窄。

**改成比對「條數與 `off` 基準是否一致」**之後，才看到真正的問題：不是「出現了不該出現的訊息」，
而是「**多了一條重複的**」。

> 教訓：**用文案特徵當斷言，等於把答案寫進測試。** 應該比對**結構**（條數、步驟、類型），
> 而不是比對措辭。這一條與 S1 的「`includes('x')` 前先問別處有沒有這字串」是同一個家族。
