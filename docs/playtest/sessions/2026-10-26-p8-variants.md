## 七、方法論教訓（給下一輪的自己）

1. **一次 `eval` 只能點一顆按鈕。** React 在單次 `eval` 內不重繪，同步迴圈會反覆點到**同一顆**
   ——第一版「進入全部編輯模式」只讓第一個職業生效，4 條斷言誤報成「變體不見了」。
   修法：一次 `eval` 點一顆，`await wait()` 讓 React 重繪後再點下一顆。
2. **按鈕文字要「含子字串」，不要「精確等於」。** 「展開」是「此團開卡規則」那顆 header 按鈕裡的一個 span，
   `innerText.trim() === '展開'` 永遠找不到。改成 `includes('此團開卡規則')` 才對。
3. **台賬分母會少算，先看測試檔的斷言。** 計畫寫 7、矩陣寫 7，但 `coreBookVariants.test.mjs` 早就斷言 8。
   → 對數字有疑問時，**測試檔的斷言比計畫書的括號可信**。
4. **「不受開關控制」不等於「壞了」。** 43 筆新增英雄技能永遠顯示，但開關的提示寫的是
   「核心技能變體與秘儀師變體」——範圍本來就不同。**先讀開關的說明文字，再判它該不該關掉某批內容。**
