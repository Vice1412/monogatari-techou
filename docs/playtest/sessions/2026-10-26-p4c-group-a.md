## 二、修法：把「數什麼」講清楚，不是把數字調成一樣

### 2.1 為什麼不能統一成一個數字

第 2 步在魔晶石模式下有**兩條** error。那是 **2 項、1 步**。
把「步驟數」和「條數」硬湊成一樣，等於把「每步有幾條」這個資訊丟掉——
而那正是玩家要的（他要先處理有兩條的那一步）。

所以修的是**語意**：每個數字都說自己在數什麼。

### 2.2 用詞

| 詞 | 意思 | 擋不擋定稿 |
|---|---|---|
| **必須修正** | `type === 'error'` | 擋 |
| **提醒** | `warning` ＋ `info` | 不擋 |

以前頁首只講前者，8 條提醒在畫面上完全沒有數字。
現在頁首寫：「還有 2 項必須修正，**另有 8 項提醒**，補完後即可定稿。」

### 2.3 `deriveCreationState()` 成為唯一來源

`characterEngine.js` 新增一支純函式，回傳：

```
blockerCount / suggestionCount       條數（頁首、兩個徽章用）
blockerSteps / suggestionSteps       分布在哪些步驟
canLock                              能不能定稿
lockHint                             灰掉時要說的原因（F-005）
blockerLabels                        壓成一句話的缺口名（F-005）
checklist / checklistById            每步狀態（導航列用）
validation                           原始驗證結果（彈窗用）
```

畫面上**四個**原本各自 `filter` 一遍的地方全部改成讀它：

| 位置 | 以前 | 現在 |
|---|---|---|
| 頁首 | 有 error 的**步驟數** | `blockerCount`（條數） |
| 自檢卡徽章 | `validation.errors.length` | `blockerCount` |
| 快捷列緊湊徽章 | 又一份自己的 `filter` | `blockerCount` |
| 導航列圓點 | 每步一個，沒有數字 | 每步一個 ＋ `title` 說幾項 |

### 2.4 導航列：顏色與圖例

原本兩個點都是深紅（`#8c2d36` 與 `#a63d40`），**畫面上分不出來**——
於是「哪個點擋定稿」變成要猜的事。

| 狀態 | 顏色 | 圖例 |
|---|---|---|
| 必須修正 | `#8c2d36` 深紅＋外環 | `● 必須修正` |
| 提醒 | `#9c4d16` 琥珀（取自 `identityPalette.amber`） | `● 提醒` |
| 完成 | 打勾 | — |

圖例放在「創角流程」標題右側，一行。每步的 `title` 自己說數字：
「第 2 步：1 項必須修正、1 項提醒」／「第 3 步：1 項提醒（不擋定稿）」。

## 三、F-004：改名，不是停用

頁尾「完成創角，進入跑團面板」→「**先去看跑團面板（尚未定稿）**」。

**為什麼不停用**：先去看看面板是合理需求（想看這張卡實際長什麼樣）。
原本的錯不是「允許預覽」，是**用同一個名字講兩件相反的事**。

所以 `locked` 仍然不會被設，但按鈕已經自己說了「尚未定稿」，`title` 也說
「這顆只帶你去看面板目前長什麼樣，不會定稿」。

實機截圖：`scratch/p4c-footer-button.png`——兩顆按鈕並排，一眼看得出是兩件事。

## 四、F-005：被 F-010 擋住的那一條

要「列出缺口」，就得先知道「缺口有幾條、叫什麼」——
而原本那三個數字各算各的，**沒有任何一個地方答得出來**。
所以 F-005 實際上是**被 F-010 的解擋住的**。先做單一來源，它才有東西可以列。

現在的 `title`：
> 尚缺：尚未選擇任何職業、起始資金尚未結算 —— 點左側「規則自檢」看詳情

缺口名稱不直接塞原始訊息——原文常帶括號補充與破折號解釋，塞進 tooltip 會爆版。
多了一支純函式 `shortIssueLabel()`，切在第一個「（／(／——／；」之前：

```
起始資金尚未結算（原書 p.165：剩餘預算 ＋ 2d6 × 10）——目前顯示的 500z 是裝備預算，不是起始資金
→ 起始資金尚未結算
```

## 五、兩個「護欄寫了等於沒寫」

都靠刻意破壞驗證才發現，而且**都是同一個病**：斷言在被測物消失時自動成立。

1. 第一版：
   ```js
   buttonTexts(...).filter(t => t.includes('先去看跑團面板')).some(t => t.includes('完成創角'))
   ```
   按鈕改名消失 → `filter` 回空陣列 → `some` 在空陣列上回傳 `false` → **斷言永遠通過**。

2. 第二版改成「找文字含『跑團面板』的按鈕」——**還是抓錯**，
   因為快捷操作區也有一顆「跑團面板」。

最後給頁尾那顆加 `data-testid="enter-play-preview"`，用 testid 定位。
**這是「別處也有這字串」的第 N 次**，只是這次發生在「找按鈕」而不是「找文字」。
